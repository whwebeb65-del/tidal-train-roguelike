# 列车长成长手册设计

## 目标

在不增加强制弹窗、新货币或付费任务的前提下，把首次通关、升级车站、强化装备、技能进化、加入军团和账号成长串成一条清晰的新玩家路线。玩家在车站一次只看到最多三个当前目标，并能直接前往对应场景。

## 方案

成长手册作为车站主场景中的手绘站务任务板，使用票据、印章、胶带和路线涂记表现，不采用规整后台式卡片矩阵。它位于车站英雄场景之后、地图和运营区之前，既足够显眼，又不遮挡列车长、列车和出发按钮。

手册包含六个顺序目标：

1. 完成一次普通航线；
2. 将车站升级到 Lv.2；
3. 将任意装备强化到 Lv.2；
4. 永久解锁任意一个技能进化效果；
5. 加入潮汐灯塔团；
6. 将账号提升到 Lv.10。

前一个目标领取后才公开下一个目标，界面同时展示当前目标以及之后两个预告目标。已完成但未领取的目标使用可操作的盖章按钮；未完成目标提供场景跳转或出发按钮；预告目标不提供操作。

## 规则与奖励

目标进度只读取现有权威状态：`PlayerSave`、装备库存、技能精通、`SocialExpeditionState` 和账号等级。成长手册不复制业务进度，只独立保存已领取目标 ID。

固定奖励如下：

| 目标 | 奖励 |
| --- | --- |
| 首次通关 | 60 齿轮 |
| 车站 Lv.2 | 2 航线徽记 |
| 装备 Lv.2 | 80 齿轮 |
| 首个技能进化 | 3 航线徽记 |
| 加入军团 | 100 齿轮 |
| 账号 Lv.10 | 120 齿轮、4 航线徽记 |

领取操作必须幂等。未知、未完成、尚未公开或已领取目标都不修改资产。清空本地存档时同步清除成长手册状态。正式服务端接入后，领取记录和资产发放必须迁移到同一个服务端事务。

## 数据边界

新增版本化 `CaptainGuidebookState`：

```ts
interface CaptainGuidebookState {
  readonly version: 1;
  readonly claimedObjectiveIds: readonly CaptainGuidebookObjectiveId[];
}
```

状态使用独立本地键 `tidal-train-captain-guidebook-v1`。读取时过滤未知 ID、去重并保持目录顺序；损坏数据回退为空状态。资产仍写回现有 `PlayerSave`，不创建第四种货币。

## 界面与交互

- 根节点使用 `.captain-guidebook.living-zone`，保证整站视觉覆盖守卫能检查。
- 当前目标展示任务标题、简短原因、进度、固定奖励和一个至少 44×44 的按钮。
- 已达成按钮文案为“盖章领奖”；未达成按钮按目标显示“检票出发”“去升级”“去装备舱”“去技能培养”“去军团码头”。
- 预告目标以线路草图形式出现，仅展示解锁条件，不制造伪倒计时或付费紧迫感。
- 领取后任务板原位更新，并通过现有站内公告反馈奖励。
- 减少动态效果时取消印章弹跳和票据漂浮，只保留状态颜色与文字。

## 埋点

新增两个不含敏感信息的事件：

- `guidebook_objective_viewed`：记录首次曝光的目标 ID；
- `guidebook_reward_claimed`：记录目标 ID、齿轮与航线徽记数量。

原型只验证事件结构；正式留存分析必须使用登录账号和服务端事件。

## 验证

- 纯规则测试：规范化、顺序公开、进度判定、幂等奖励和不可领取分支。
- 仓储测试：损坏数据回退、保存、清空和旧存档兼容。
- 视图测试：当前/达成/已领取/预告状态、跳转动作、奖励文案和语义结构。
- 运行时测试：领取写回玩家资产、场景跳转和站内公告。
- 样式与浏览器烟测：360、390、412、430 四种手机视口无横向溢出，全部可用按钮宽高不低于 44px。
- 完整门禁：测试、类型检查、资源预算、生产构建、安全审计和真实浏览器战斗回归。

## 本轮边界

本轮只实现成长手册闭环，不同时引入图鉴、服务端账号、真实支付、真实广告或推送。怪物、技能与装备图鉴作为下一批独立功能，复用成长手册验证后的入口和视觉语言。
