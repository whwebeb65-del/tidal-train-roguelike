# 全站「活的潮汐车站」非战斗界面设计

## 1. 目标

将整个游戏的非战斗界面统一成一座连续、可感知的 2.5D 潮汐车站，彻底消除当前大量重复的“标题、说明、两列圆角卡片、标准按钮”后台模板观感。

本次设计覆盖所有非战斗页面和流程状态，而不是只处理用户明确指出的车站值班铺、潮汐试炼或首班预约中心。完成后，每个系统都应像车站中的真实地点或物件，同时保持清晰、易用和可维护。

## 2. 设计原则

### 2.1 同一个世界，不是同一张皮

- 全站共享黄昏海港光线、海雾、木材、旧金属、帆布、纸票和手绘油漆质感。
- 不创建另一套统一卡片组件。不同系统必须使用符合功能含义的物件与空间。
- 每个区域拥有独立主色、构图和标志性物件，但角色比例、光影方向和材质语言一致。
- 角色、背景、界面物件必须处于同一套 2.5D 光影关系中，避免 3D 角色贴在平面后台面板上的割裂。

### 2.2 去除模板化大框

- 非必要情况下不使用包住整个系统的实体底色、统一描边、大圆角和整块阴影。
- 信息分组使用站牌、公告板、工作台、售票窗、衣架、货箱、照片墙、航线地图等真实物件。
- 页面允许高低错落、轻微旋转、局部重叠、角色和装饰越出常规内容线。
- 边缘通过雾气、光晕、前景遮挡或材质自然结束，不使用大矩形容器裁切场景。

### 2.3 花哨但可控

- 颜色强调来自区域主色、灯光、印章和奖励物件，不依赖满屏高饱和渐变。
- 环境动态幅度控制在 2–8 像素，包括灯泡轻摆、海雾漂移、旗帜呼吸、角色待机和可领取物件柔光。
- 页面不持续大幅摇晃；交互反馈短促明确。
- 完整尊重 `prefers-reduced-motion`，关闭非必要位移与循环动画。

## 3. 整站空间结构

底部导航继续承担页面切换职责，但视觉上改成车站导览牌。切换页面等价于前往同一座车站的不同区域。

### 3.1 车站首页：中央主站台

- 已完成的签到模块保留夜摊设定，并继续作为整站材质与光影基准。
- 今日潮汐试炼改成木制航迹挑战榜：规则写在站牌上，修正项使用悬挂牌，尝试次数和个人最佳使用粉笔记分，里程碑使用可点亮的航标灯。
- 首班预约、内测资格、开服礼和礼包码合并为空间连续的售票与检票区域：资格是候车票，开服礼是行李车，礼包码是检票钳与票槽。
- 航线补给站改成站台补给摊；商品是独立木箱、挂架或陈列台。
- 军团入口改成通往灯塔码头的公告与集合点。
- 车站升级、体力说明和其他辅助说明使用机械刻度牌、站务便笺和维修记录，不再使用横向信息框。

### 3.2 角色页：列车长休息室

- 角色作为空间主体站在休息室或车厢门口。
- 账号等级、角色属性和永久培养使用行李牌、值班证和墙上训练记录。
- 技能与解锁效果使用可叠加的勋章、别针和航线印章。
- 选择、锁定和升级状态通过灯光、封条、印章和物件磨损表达。

### 3.3 装备页：水獭维修工坊

- 装备摆放在工作台、挂墙工具板和零件架上。
- 强化材料使用零件盒、齿轮罐和维修标签。
- 已装备物品靠近列车或角色模型，库存物品留在工坊陈列区。
- 装备比较使用两张维修卡或悬挂标签，不使用两个标准信息卡片。

### 3.4 衣橱页：列车更衣车厢

- 皮肤展示在衣架、镜面、行李箱和车厢挂钩上。
- 角色在镜前实时显示当前外观。
- 已拥有、未解锁、可购买和已穿戴分别使用衣架灯、封条、价签和镜面高光表达。

### 3.5 商店页：漂流补给市场

- 不同商品类型使用不同摊位、木箱和陈列架。
- 价格与内容在交互前完整展示，继续遵守现有透明购买规则。
- 已购买物品表现为空陈列位、售罄牌或盖章收据。
- 不新增真实支付行为，继续使用当前 Mock 验单。

### 3.6 军团页：灯塔码头

- 军团信息使用码头旗帜、灯塔牌和集合公告。
- 支援角色是候车或登船队伍，成员身份使用照片、臂章和行李牌。
- 远征里程碑是航线图上的灯点或码头信号灯。
- 未加入、已加入、可领取和已完成状态使用不同灯号和旗帜状态。

### 3.7 设置页：列车控制柜

- 音量、动画、震动和辅助选项映射为旋钮、拨杆和控制灯。
- 危险操作独立放入带封条的维修抽屉，避免和普通设置混在一起。
- 控件仍使用原生可访问表单语义，视觉外壳不影响键盘与触控操作。

### 3.8 流程页面

- 角色选择：候车月台上的两位列车长，而不是并排角色卡片。
- 战斗前准备：调度台、航线图和出发清单。
- 胜利结算：到站月台、卸货车与奖励行李。
- 失败结算：维修站、受损列车和修复记录。
- 潮汐试炼结算：航迹榜更新与成绩印章。

## 5. 交互与状态语言

- 主操作文案结合物件语境，例如“敲钟开赛”“撕下车票”“打开零件箱”“登上航线”，但不得改变真实行为。
- `data-action`、领域模型、存档结构、奖励数值、解锁条件和资源结算保持不变。
- 可领取：灯光点亮、挂牌翻面或短周期柔光。
- 已领取：盖章、空陈列位或收据。
- 锁定：封条、熄灯、链条或上锁行李箱，并保留明确的解锁条件文字。
- 资源不足：价签变色并显示实际差额，不只依赖颜色。
- 空数据：展示空置物件与下一步引导，不显示空白大框。
- 日期异常：签到与日常区域使用停摆时钟和站务警示，继续禁用相关操作。
- 加载或处理中：使用短暂的检票、装箱或维修动作，防止重复操作。
- 错误提示必须靠近触发物件，并保持可读文本，不只使用动画。

## 6. 响应式设计

- 桌面端允许场景横向延展、物件重叠和角色破界。
- 手机端改成纵向场景叙事，不采用简单的“双列变单列”机械压缩。
- 重要操作按自然阅读顺序出现，底部导航保持固定、易点击且不遮挡主要按钮。
- 角色和装饰可裁切，但奖励数值、状态、解锁条件和操作按钮不得被遮挡。
- 360、390、412、430 像素宽度均不得出现横向滚动。
- 触控目标保持至少 44×44 CSS 像素；文本缩放后仍可使用。

## 7. 技术边界

### 7.1 保持稳定的内容

- 不修改领域系统、游戏数值、战斗机制、存档版本或资源经济。
- 不修改现有动作标识和业务调用关系。
- 现有素材目录和资源预算规则继续生效。

### 7.2 表现层组织

- 为每个区域增加语义明确的根类和独立样式范围，避免继续被通用 `.system-card`、`.system-card__item` 和 `.system-card__badge` 覆盖。
- 共享层只包含光线、材质、雾气、场景深度、动画幅度和状态语义，不包含统一卡片外形。
- 优先复用现有车站分层背景、角色、怪物、技能和奖励素材。
- 新增视觉内容优先采用轻量 CSS 物件和可复用小型装饰；只有在 CSS 无法匹配现有 2.5D 画风时才新增少量图像资产。
- 避免继续向单一 `legacy.css` 堆叠全部逻辑；新增场景样式按区域拆分，并通过现有样式入口按明确顺序引入。

## 8. 实施批次

### 批次一：车站首页

覆盖日常试炼、首发活动、礼包码、补给商店、军团入口、车站升级和辅助说明。签到夜摊作为光影与材质基准，只做必要的整页融合调整。

### 批次二：主导航页面

覆盖角色、装备、衣橱、商店、军团和设置。每个页面形成独立地点，并共享车站世界基础层。

### 批次三：流程页面与全站收尾

覆盖角色选择、战斗前准备、胜利结算、失败维修、潮汐试炼结算、页面转场、响应式细节和全站一致性检查。

三个批次连续实施，不能在只完成车站首页时宣称全站改造完成。

## 9. 验收标准

1. 所有非战斗主页面均有独立地点设定和标志性物件。
2. 不再存在包住整个功能区域的模板化大圆角系统面板。
3. 不同系统的主操作、状态和空态具有符合场景语境的视觉表达。
4. 角色、背景和界面物件在光影、比例与层级上保持一致。
5. 所有原有业务动作、数值、存档和解锁规则保持通过。
6. 完整单元测试、类型检查、资源预算和生产构建通过。
7. 真实浏览器验证桌面端及 360、390、412、430 像素手机端。
8. 无横向溢出、遮挡关键操作、重复导航、控制台错误或资源加载失败。
9. `prefers-reduced-motion` 下非必要循环动画关闭。
10. 三个实施批次全部完成后，才可推送为全站视觉改造版本。
