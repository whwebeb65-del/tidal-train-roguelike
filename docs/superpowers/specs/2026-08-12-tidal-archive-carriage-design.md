# 潮汐档案车厢设计

## 1. 背景

《最后一班：潮汐列车》已经具备八种潮兽、十二种技能进化、八件装备和两套装备套装，但这些内容只在战斗或工坊当下出现。玩家离开对应页面后，没有地方回看自己见过什么、还缺什么、去哪里获得，也缺少一个不依赖新货币和数值膨胀的长期收藏目标。

本轮将“海獭维修工坊”扩展为“工坊 / 潮汐档案”双页签车厢。档案使用真实战斗事件和现有库存点亮，不发奖励、不改战斗数值、不增加付费随机内容。

## 2. 目标

- 玩家可在现有装备入口内一键切换到潮汐档案，不增加第六个底部导航项。
- 展示 8 种潮兽、12 种技能进化和 8 件装备图纸的收藏进度。
- 潮兽只在真实生成后记为已遇见；技能进化只在真实选择后记为已发现；装备按当前库存自动点亮。
- 已发现条目显示名称、插图、机制说明和搭配建议；未发现条目显示剪影、来源提示和明确的解锁方向。
- 档案状态刷新后保留，清空本地存档时同步删除；损坏或未知 ID 安全过滤。
- 手机 360、390、412、430px 下无横向溢出，所有页签按钮至少 44×44，减少动态效果时无位移动画。

## 3. 非目标

- 不新增货币、收藏奖励、属性加成、成就点或付费概率内容。
- 不增加新的底部导航项，不重做装备强化、升星或重铸规则。
- 不记录战斗坐标、用户身份或个人信息。
- 不伪造“全服发现率”、倒计时、稀缺度或尚未存在的掉落来源。
- 不在本轮实现乘客图鉴、赛季图鉴、搜索、排序或服务端同步。

## 4. 入口与体验

### 4.1 工坊双页签

装备场景顶部保留“海獭维修工坊”招牌，在招牌下增加两枚实体车票页签：

- `维修工作台`：现有装备、套装和四类操作，默认打开。
- `潮汐档案`：收藏进度和三册档案。

切换只改变当前装备场景的页面内容，不修改底部导航和 URL；离开装备场景后可以保留本次会话选择，刷新后回到工作台。页签使用 `aria-pressed` 表达当前状态。

### 4.2 潮兽观察册

目录固定为八种现有 `EnemyKind`。战斗引擎产生 `enemy-spawned` 事件后，运行时将其 ID 幂等写入档案状态。普通航线与每日试炼都可记录真实遭遇，因为记录不发奖励，也不改变挑战结果。

已遇见条目显示现有 Q 版潮兽图、中文名、战场职责、应对提示和首次来源；未遇见条目对同一资源做深色剪影处理，名称显示为“未记录潮兽”，但保留真实来源提示，例如“漂流郊区后段”或“Boss 潮头”。

### 4.3 技能进化标本册

目录固定为 `SKILL_VARIANT_IDS` 的十二项。只有 `upgrade-selected` 事件的定义类型为 `skill-variant` 时才点亮；仅因技能精通达到门槛、进入三选一候选池，不算发现。

已发现条目显示现有进化徽记、名称、效果与协同建议；未发现条目显示剪影、所属技能和精通门槛。这样玩家能知道长期目标，但不会提前把完整机制内容当作已获得能力。

### 4.4 装备蓝图册

目录来自 `EQUIPMENT_CATALOG`。当前库存中存在同 `definitionId` 的实例即点亮，无需复制持久化状态。已拥有条目显示名称、槽位、稀有度、套装和基础属性；未拥有条目显示槽位蓝图、套装与真实来源。四件初始“潮泡守望”装备默认点亮，四件“珊瑚突击”装备按实际购买或库存状态点亮。

## 5. 状态与规则

新增纯领域模块 `src/domain/collection/TidalArchiveSystem.ts`：

```ts
export interface TidalArchiveState {
  readonly version: 1;
  readonly discoveredEnemyKinds: readonly TideBeastArchiveId[];
  readonly discoveredSkillVariantIds: readonly SkillVariantId[];
}
```

模块提供安全默认值、规范化、敌人发现和技能进化发现四类操作。规范化只接受当前目录中的 ID，按目录顺序去重；发现同一条目返回同一对象引用，避免重复存储和重复遥测。

独立存储键为 `tidal-train-tidal-archive-v1`，由 `AppStateRepository` 统一读取、保存和清空。装备发现不写入该键，始终从权威的 `PlayerSave.equipmentInventory` 派生。

`TideBeastArchiveId` 成为战斗 `EnemyKind` 的领域别名来源，避免档案和战斗各维护一份可能漂移的字符串联合类型。

## 6. 生产运行时数据流

1. `LegacyGameRuntime` 加载档案状态。
2. `BattleScene` 已有的 `onBattleEvents` 将真实事件交给运行时。
3. `trackBattleEvents` 在处理遥测的同时：
   - `enemy-spawned` → 发现潮兽；
   - `upgrade-selected` 且定义为 `skill-variant` → 发现技能进化。
4. 只有状态对象真实变化时才保存，并记录一次发现遥测。
5. 装备场景渲染时读取档案状态、技能精通等级和当前装备库存，生成纯 ViewModel。
6. `EquipmentView` 只渲染当前页签和转发页签按钮，不直接读存储或解释战斗事件。

页面切换状态为运行时内存字段 `equipmentPanel: 'workshop' | 'archive'`。点击 `show-equipment-workshop` 或 `show-tidal-archive` 后刷新当前场景；切换不写本地存储。

## 7. 目录与文案边界

新增 `web/views/TidalArchiveCatalog.ts`，集中维护：

- 潮兽名称、插图映射、战场职责、应对提示和来源；
- 技能进化名称、效果、协同建议、所属技能和精通门槛；
- 装备槽位、套装、稀有度和来源的展示文案。

技能进化名称与效果复用战斗升级的权威文案导出，不复制第二份可能漂移的文字。潮兽插图复用 `BATTLE_ART_URLS`，技能进化徽记复用 `BATTLE_VARIANT_GLYPH_URLS`，不新增图片资产。

## 8. 视觉与交互

- 档案页使用旧车票、压花编号、海图网格、绳结和实物标本夹，继续当前 2.5D 手绘车站语言。
- 三册使用不同强调色：潮兽为珊瑚橙，技能进化为紫金，装备蓝图为青蓝；不使用通用玻璃卡片或均匀网格边框。
- 已发现图像保持原色并带手写批注；未发现图像使用高对比剪影和问号火漆章。
- 桌面每册可两到四列，移动端采用一列或两列不等宽卡片；信息层级优先保证名称、状态和来源可读。
- 所有装饰伪元素 `pointer-events: none`；页签、按钮和链接至少 44×44。
- `prefers-reduced-motion: reduce` 下取消页签抬起、票据轻摆和新发现呼吸效果。

## 9. 遥测

新增：

- `tidal_archive_viewed`：档案首次打开时记录已发现潮兽、技能进化和装备数量；
- `tidal_archive_entry_discovered`：记录 `entryType` 与 `entryId`，同一条目只记录一次。

不发送战斗坐标，不把查看行为与奖励、广告或付费绑定。当前原型仅验证事件结构；正式留存分析仍需登录账号与服务端事件。

## 10. 验收与发布门禁

- 领域测试覆盖默认、损坏输入、未知 ID、目录排序、重复发现与不可变性。
- 存储测试覆盖读取、保存、刷新和 `clear()` 删除新键。
- 运行时测试证明真实 `enemy-spawned` 与真实技能进化选择各只发现一次，普通/试炼均可记录敌人且不发资产。
- View 测试证明三册总数、已发现/锁定状态、来源、权威技能文案和装备库存派生正确。
- 浏览器 smoke 打开档案页，检查移动视口无横溢、页签双轴至少 44px、所有已显示图片加载成功，并在真实战斗后确认潮兽进度增长。
- 发布前通过 `npm test`、`npm run typecheck`、`npm run check:assets`、`npm run build`、`npm audit --audit-level=high`、`npm run smoke:browser` 和 `git diff --check`。

## 11. 回滚

档案不影响战斗和资产。若上线后出现视觉或性能问题，可移除装备页签与运行时发现接线，同时保留独立存储键；未知键不会影响旧版本，清空本地存档仍会删除它。
