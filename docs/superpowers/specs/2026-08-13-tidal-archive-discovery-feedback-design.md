# 潮汐档案发现反馈链设计

## 目标

让潮兽首次出现和技能进化首次选择成为玩家能感知、能回看、不会打断战斗的收藏时刻。当前档案已经能正确记录发现，但玩家只有主动进入装备舱后才知道记录发生了；本轮补齐战斗内提示、结算汇总、持久未读和档案内新条目标记。

本轮只增强反馈，不增加货币、战力、收藏奖励、付费入口或随机内容，也不改变敌人生成、技能进化、装备、结算和广告规则。

## 方案选择

采用“专用发现票 + 结算行李签 + 档案封蜡未读”的混合方案。

- 不采用货币或属性奖励。那会把自愿收藏变成强制养成，并扩大经济通胀。
- 不复用全局站内公告。公告在战斗覆盖层中会被隐藏，也无法承载图片、条目类型和队列。
- 不暂停战斗或强制玩家点击。发现票是非交互提示，出现后自动退场；低动态模式只取消移动与旋转，不取消信息。

## 玩家体验

### 战斗中

当真实 `enemy-spawned` 事件第一次写入某种潮兽，或真实 `upgrade-selected` 事件第一次写入某个技能进化时，战斗 HUD 右上安全区出现一张手绘发现票：

- 眉题为“NEW ARCHIVE ENTRY”；
- 展示条目图片、类型和真实名称；
- 潮兽文案为“首次目击已装订”，技能进化文案为“新进化标本已归档”；
- 每张展示 2400ms，多条发现按顺序排队；
- 不捕获指针、不暂停模拟、不修改射击或技能输入；
- 暂停、升级、失败、结算和首次教学覆盖层存在时不展示，待回到可战斗状态后继续队列；
- `prefers-reduced-motion: reduce` 时取消票据滑入、倾斜和弹跳，保留静态票据与文本。

同一条目重复出现时不会再次提示，因为领域发现转换保持幂等。

### 结算时

每局首次发现的条目追加到该局的结算展示中，在既有奖励行李下方出现“本局新档案”行李签。普通胜利、失败撤回和每日试炼都使用同一份本局列表；它只显示条目，不改变任何结算数值。

最多展示本局全部首次发现条目。正常十分钟战斗的理论上限低于目录总量，布局在手机端允许换行并保持返回按钮可见。

### 回到装备舱

“潮汐档案”票签显示持久未读封蜡，例如 `NEW 2`。未读只计算潮兽和技能进化，装备条目继续由现有库存实时推导。

玩家打开档案时：

1. 将当前未读键复制为本次浏览的新条目集合；
2. 立即把持久未读清零并写回存档；
3. 本次页面内对应卡片仍显示红色 `NEW` 印章，保证玩家能看见刚刚清掉的内容；
4. 切回工作台或离开装备场景后清除本次浏览集合；下次进入不再显示印章。

## 数据模型

`TidalArchiveState` 升级为版本 2：

```ts
export type TidalArchiveEntryKey =
  | `enemy:${TideBeastArchiveId}`
  | `skill-variant:${SkillVariantId}`;

export interface TidalArchiveState {
  readonly version: 2;
  readonly discoveredEnemyKinds: readonly TideBeastArchiveId[];
  readonly discoveredSkillVariantIds: readonly SkillVariantId[];
  readonly unreadEntryKeys: readonly TidalArchiveEntryKey[];
}
```

规范化规则：

- 版本 1 存档保留已发现列表，但迁移后的未读为空，避免老玩家上线时收到历史条目轰炸；
- 版本 2 只保留格式合法且已经发现的未读键；
- 未知、重复、与发现列表不一致的未读键被过滤；
- 未读按“潮兽目录顺序，其后技能进化目录顺序”排列；
- 根状态和三个数组全部冻结；
- 重复发现返回原引用；首次发现同时追加发现列表与未读键；
- `markTidalArchiveRead` 在未读为空时返回原引用，否则只清空未读，不改变发现记录。

仓储键保持 `tidal-train-tidal-archive-v1`，由内容版本完成兼容迁移，避免并存两个键和双写风险。

## 表现模型与运行时边界

新增 UI 表现类型 `TidalArchiveDiscoveryPresentation`：

```ts
interface TidalArchiveDiscoveryPresentation {
  readonly key: TidalArchiveEntryKey;
  readonly entryType: 'enemy' | 'skill-variant';
  readonly entryId: string;
  readonly name: string;
  readonly artUrl: string;
}
```

名称和图片复用权威档案目录与战斗进化文案，不复制第二套可漂移的文案。

`LegacyGameRuntime.trackBattleEvents` 在状态真正变化时返回本批新增表现，并把它们加入本局发现列表。`BattleScene` 接收返回值并拥有纯表现队列与 2400ms 展示时钟；运行时仍是持久化和遥测的唯一所有者，场景不写存档。

`BattleSettlementPresentation` 增加只读 `archiveDiscoveries`。所有正常、每日试炼、失败和重复结算构造函数都显式提供该字段；重复结算不重复创建发现。

装备场景渲染输入增加 `archiveUnreadCount` 和 `archiveVisitNewKeys`。点击档案票签时清未读，点击工作台或离开装备场景时清本次浏览集合。未读清除不发送经济事件；新增一个 `tidal_archive_entries_read` 遥测，载荷只有清除数量。

## 视觉规则

- 发现票使用奶油纸、红色归档章、青蓝潮兽边和紫金进化边，沿用现有档案材质而不增加图片资产。
- 票据宽度在手机端不超过可视宽度减 24px；不覆盖顶部生命栏、右侧速度/暂停、底部技能和升级/结算操作。
- 结算行李签在奖励与成长信息之后、操作按钮之前，允许两列自动换行。
- 档案票签封蜡和卡片 `NEW` 印章都是装饰层，`pointer-events: none`。
- 所有新增可操作元素仍满足 44×44；本轮没有新增必须点击的战斗控件。

## 失败与恢复

- 图片加载失败时仍显示文本、类型和 CSS 图章，不阻塞战斗或档案打开。
- 损坏未读数据被规范化为空或合法子集，不影响已发现记录。
- 战斗退出、失败或场景销毁时清空场景展示队列；本局汇总由运行时保存到当前结算表现。
- 存档写入失败沿用现有仓储行为，不创建另一份临时资产或补偿货币。

## 验证

- 领域测试：v1→v2 迁移、未知/重复/孤立未读过滤、目录顺序、嵌套冻结、首次发现新增未读、重复发现幂等、清未读幂等。
- 仓储测试：版本 2 往返、版本 1 兼容、损坏恢复和全局清除。
- 运行时测试：普通与每日试炼真实事件只在首次发现时写入未读/遥测/本局汇总；打开档案清持久未读但保留本次 NEW；离开后清临时 NEW；玩家资产与 BattleRunInput 不变。
- 场景/HUD 测试：2400ms 队列、覆盖层期间暂停展示、队列顺序、结算汇总、非交互语义和图片替代文本。
- 样式测试：作用域、指针穿透、手机宽度、结算换行和低动态静态化。
- 真实 Chrome：360/390/412/430 四视口，真实战斗生成发现票，结算展示本局新档案，回站后未读封蜡存在，打开后卡片保留 NEW，重新进入后消失；图片加载、无横溢、按钮不遮挡；390 两局胜利和普通 URL 无 E2E 暴露继续通过。

## 本轮边界

不增加收藏完成奖励、外观皮肤、成就点、第四种货币、红点推送、音效资产、服务端账号同步或付费内容。收藏奖励可在未来作为独立版本评估，前提是先验证档案访问和回看行为。
